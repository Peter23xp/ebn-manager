# EBN MLM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace legacy referral and loyalty features with an auditable eight-level MLM system, including member progression, wallets, bonuses, salaries, and seven protected screens.

**Architecture:** `Client` remains the commercial identity and receives one `Membre` profile after onboarding activation. A NestJS MLM module owns all financial transactions and matrix promotion rules, while React pages consume typed REST clients through TanStack Query. Financial state is only changed in Prisma transactions; the frontend never calculates commissions or promotions.

**Tech Stack:** React 18, TypeScript, Vite, Tailwind CSS, TanStack Query v5, Zustand, NestJS 10, Prisma 5, PostgreSQL, Jest, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-17-ebn-mlm-design.md`

## Global Constraints

- Keep the current repository layout: `frontend/` and `backend/`; do not introduce `apps/client` or `apps/server`.
- Use `Decimal(12,2)` for all MLM USD amounts; never use `Float` for financial amounts.
- A client gains exactly one MLM profile when onboarding activation succeeds.
- A matrix has exactly four positions and a promotion/commission update is one Prisma transaction.
- JWT role hierarchy remains `SUPER_ADMIN > DIRECTEUR_REGIONAL > GERANT > AGENT > FORMATEUR > CLIENT`.
- A `CLIENT` may request only their own MLM data; server-side site scoping is mandatory for `GERANT`.
- Legacy referral/loyalty tables, modules, routes and navigation entries are removed in the same release.
- Preserve historical sales records; legacy sales point/remise fields may remain read-only but must no longer be written.
